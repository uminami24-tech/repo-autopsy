# 日本語レポートの文体規則

## 基本文体

- **です・ます調**で統一する（断定の「だ・である」は使わない）。
- 読者は非専門家の個人開発者を想定し、平易な表現を優先する。

## 専門語の扱い

- 専門用語・英語略語は **初出時に括弧で日本語説明** を添える。
  - 例: `arm64（Apple Silicon 向けの CPU アーキテクチャ）`
  - 例: `dry-run（実際にはコマンドを実行せず、内容を確認するだけのモード）`
- 2 回目以降はそのまま使ってよい。

## 断定の回避

- 判定はあくまで **一次判定** であることを、判定ラベルの直後に必ず明記する。
  - 例: `判定: 罠（一次判定。実際の動作は環境により異なります）`
- 「必ず動く」「絶対に罠」などの断言を避ける。

## 英語の残存禁止

- レポートの見出し（`#` `##` `###`）はすべて日本語にする。
- 英語のままの段落・箇条書きを残さない。コマンド・コードブロックは除く。
- README からの引用はブロッククォートに入れ、直後に日本語訳を添える。

## 数値・単位

- 時間は「X 分 Y 秒」、ファイルサイズは「X MB」と単位を明記する。
- 日付は「YYYY-MM-DD」形式（ISO 8601）を使う。

## レポート末尾の定型文

レポートの最後に必ず以下を付記する：

```
---
本レポートは Repo Autopsy による自動生成です。内容は一次判定であり、動作を保証するものではありません。
検証日: YYYY-MM-DD ／ 環境: macOS XX.X（Apple Silicon）
```
